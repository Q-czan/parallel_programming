# Задача 2. Сглаживание массива

## Условие

Объявлен массив из 16000 элементов, инициализированный `a[i] = i`. Создать результирующий массив `b`, в котором (кроме крайних элементов) будут средние значения исходного массива:

b[i] = (a[i-1] + a[i] + a[i+1]) / 3.0

Запустить программу с 8 потоками при различных типах распределения работ.

## Файл

`task2.cpp`

## Сборка

g++ -fopenmp task2.cpp -o task2.exe

## Запуск

set OMP_SCHEDULE=<тип>
task2.exe <число_потоков> <размер_массива>

Примеры:

set OMP_SCHEDULE=static
task2.exe 8 16000

set OMP_SCHEDULE=dynamic
task2.exe 8 16000

set OMP_SCHEDULE=guided
task2.exe 8 16000

set OMP_SCHEDULE=static,1000
task2.exe 8 16000

set OMP_SCHEDULE=dynamic,100
task2.exe 8 16000

## Пояснение

В программе используется `#pragma omp parallel for schedule(runtime)`. Тип распределения задаётся через переменную окружения `OMP_SCHEDULE`, что позволяет перебирать варианты без перекомпиляции.

| Тип | Поведение |
|-----|-----------|
| static | Итерации равномерно делятся между потоками. |
| dynamic | Поток забирает следующий блок итераций по завершении предыдущего. |
| guided | Размер блока динамически уменьшается по мере выполнения. |
| static,1000 | Статическое распределение блоками по 1000 итераций. |
| dynamic,100 | Динамическое распределение блоками по 100 итераций. |

## Результаты запусков

Для всех типов schedule значения b[i] одинаковы:
b[1]     = 1
b[n/2]   = 8000
b[n-2]   = 15998

Время выполнения на 16000 элементах ~0.0001 с. Разница между типами распределения в пределах погрешности, поскольку задача маленькая и нагрузка на итерацию равномерная. Динамическое распределение (dynamic) обычно медленнее статического на равномерной нагрузке из-за накладных расходов на захват блоков итераций.
