# Задача 3. Вывод идентификаторов в обратном порядке

## Условие

Модифицировать задачу 1 так, чтобы потоки печатали свои идентификаторы в обратном порядке (от `N-1` до `0`).

Существует как минимум 5 способов решения. Реализовано 5 различных подходов.

## Файл

`task3.cpp`

## Сборка

g++ -fopenmp task3.cpp -o task3

## Запуск

./task3 <число_потоков> <номер_метода>

**Примеры:**

./task3 8 1
./task3 8 2
./task3 8 3
./task3 8 4
./task3 8 5

## Реализованные методы

| Номер | Метод | Принцип |
|-------|-------|---------|
| 1 | Барьер в цикле | Каждый поток проверяет свою очередь в цикле `for (turn = n-1; turn >= 0; --turn)` и печатает, когда `id == turn`. После каждой итерации — `#pragma omp barrier`. |
| 2 | Критическая секция + busy-wait | Общая переменная `turn` инициализируется значением `n-1`. Поток в цикле проверяет `turn == id`; при совпадении печатает и уменьшает `turn` внутри критической секции. Используется `#pragma omp flush(turn)`. |
| 3 | Блокировки OpenMP | Аналогичен методу 2, но для защиты `turn` используется `omp_lock_t` вместо критической секции. |
| 4 | Флаги | Каждый поток ожидает, пока следующий по номеру поток не установит флаг `printed[id+1] = true`. После этого печатает свой идентификатор и устанавливает свой флаг. |
| 5 | Барьер перед проверкой | Цикл `for (i = n-1; i >= 0; --i)`; перед каждой проверкой — `#pragma omp barrier`, затем поток с `id == i` печатает. |

## Ожидаемый вывод (для 4 потоков, любой метод)

Метод N: Поток 3
Метод N: Поток 2
Метод N: Поток 1
Метод N: Поток 0

Порядок вывода строго обратный: от `N-1` до `0`.

## Замечание

Методы 2 и 3 используют активное ожидание (busy-wait), что может приводить к повышенной нагрузке на процессор. Методы 1 и 5 используют барьеры и более эффективны с точки зрения синхронизации, но требуют, чтобы все потоки были задействованы.
